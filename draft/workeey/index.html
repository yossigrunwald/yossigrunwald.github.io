How I built Workeey

I'm Yossi Grunwald, the founder of Workeey, an app that runs a small trade business in one place. I built Workeey myself, directing a team of AI agents that write and test the code. I started in June 2026, and a few months later it was a live product.

What Workeey is

Workeey is made for plumbers, electricians, HVAC techs, handymen and freelancers. It is free to start, and it follows a job from quote to payment.

A job starts with a price. Workeey builds an estimate from the tradesperson's own rates right on the job, ready to send as a quote PDF. A separate free tool from Workeey, Quote Links, turns a quote into a link the customer can approve online, with no app and no account.

Then the job goes on the calendar. When the work is done, the invoice goes out with a way to pay online, and reminder texts can follow if it is not paid.

Workeey also keeps client records, photos, notes, receipts and expenses, and on its paid plans it links to QuickBooks and Google Calendar. An AI assistant on every screen takes a request in plain words and prepares the job, the client or the invoice. One tap confirms it.

Why I built it

People in the trades should be able to finish the job and go home, not start a second shift of paperwork. That is why I built Workeey.

That second shift is quotes, invoices and chasing payment. The work happens on site, so the paperwork should be finished there too.

I built Workeey as one app for the phone. Anything added with no signal is saved and syncs when the phone is back in range.

How I run a team of AI agents

I decide what Workeey does, and I run about ten agents at once. Each one owns one area, such as invoices, the phone app or the public pages.

Every decision I make is written down as I make it, and every past conversation can be searched, so an agent looks things up before it asks me twice.

No change goes live without being checked. Every change of any substance is read by one review agent for bugs and by another against the written design rules. Anything risky is also clicked through in a real browser.

Then a single manager agent, the only one allowed to put work live, runs the tests. A small change runs only the test suites it can affect. A change that touches shared parts runs all of them, more than 600. When a test fails, the result is compared with the live version, so an old problem is not mistaken for a new one. Once the change is live, the agent that built it checks it on the real site the way a user would.

By November 2026, about 2,650 changes had gone into the live product.

What I learned building Workeey

I built that process one problem at a time. It did not start out orderly.

Before there was a manager agent, each agent put its own changes live, and they broke each other's work. Now work reaches the live product one way only: through the manager agent, after the tests.

Some test suites reported success even when something inside them had failed. A cleanup pass found those suites, and now they fail when they should.

In the first months, the same kind of mistake kept coming back on different screens. I saw that correcting each screen was not enough, because the reasoning behind the mistake had not changed. Since then, when I correct an agent, it writes down the fix and where its reasoning went wrong, so the same kind of error does not come back somewhere else.

Each time, I fixed it with structure: one way to go live, tests that fail when they should, and corrections that are written down. I decide what gets built, the agents write the code, and the system I built around them keeps it right.

Where it is now

Workeey is live on the web, and the Android app is on Google Play. As I write this, in November 2026, the iPhone app is in review at Apple and the public site is rolling out in 13 languages.

I run Workeey from Brooklyn, New York, and I am still building it. If you want to hear more, tell me a good time to talk.
