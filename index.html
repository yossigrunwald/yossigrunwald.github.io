                    AI Automation Builder

                    Independent · 2026 to present

                    Most AI tools answer questions. Mine do the work: they plan it, check their own output and come to me only when a decision is mine.

                    I built these systems with AI. I can build one for your business.

                    1. One agent that runs a whole team

                      I talk to a single agent in plain words. It brings in other agents as the job needs them, collects their reports and gets it done without stopping for my approval at every step.

                      See more detailsHide details about the agent team

                      I talk to one agent, in plain words, from my phone. When a job needs more hands, it brings in other agents and gives each one a part. They report back to it, and it reports to me. I never have to open a browser myself or sign off on every step.

                      What it handles, for example
                      • Browser work. Clicks through a website in a real browser, the way a visitor would, and reports what broke.
                      • Posting. Posts to social media on a schedule.
                      • Reviews. Separate agents check every significant change for bugs and against written design rules.
                      • Testing and release. Runs the tests, and only one agent is allowed to put finished work live.
                      • Reports. An evening report on page speed and what needs attention, plus spoken updates I can listen to.
                      • Site watch. Watches a live website around the clock and alerts me if it goes down.
                      • Reaching me. A phone line that calls me when a question waits on me.

                      What I ask for gets done without the agent asking me again. Only a risky idea the agent came up with itself gets one plain question first.

                      How it got there

                      Early on, agents put work live on their own and broke each other's work, fought over one browser, and some test runs reported success even when tests had failed. The fix was structure: one agent allowed to put work live, a browser for each agent, one queue for heavy test runs, and tests that fail when they should.

                    2. Social posting that checks its own work

                      Automated daily social video on three platforms. Before anything can post, automatic checks confirm each voice says its script, inspect the key frames and enforce each platform's rules; anything below standard is rebuilt, not published.

                      See more detailsHide details about social posting

                      Every afternoon an agent reads the previous day's results and the standing rules, plans the next day's posts from a fixed mix of formats and writes the scripts. The videos are then built, voiced and rendered; heavy renders go to a cloud machine that switches itself off when the job is done.

                      Quality control

                      Nothing is queued until it passes:

                      • Voice. Every voiced video is transcribed and compared with its script, so each line is said as written.
                      • Picture. The first frame, every cut, the last frame and the loop point are pulled as stills and inspected.
                      • Platform rules, written into code. Captions stay clear of the on-screen buttons, no two slides look alike, and no sales lines go into captions.
                      • Privacy. In screen recordings, real personal details are replaced with made-up ones, and a text-reading pass over every frame confirms nothing real is visible.

                      Anything that fails is rebuilt, not posted.

                      I stay in charge

                      Each night I get a one-page plan of the next day's posts and can change or stop anything. Anything new, like a format or a style, waits for my pick. Posts go out hours apart under a firm daily cap, after the data showed that posting more reached fewer people. A nightly analysis feeds what worked into the next plan.

                    3. Fully automated trading

                      AI made the judgment calls, and plain code enforced safety limits the AI could not override.

                      See more detailsHide details about trading

                      I wanted a system that would trade the way I would and watch the market far more closely than I can. I explained to the AI how I trade, built the program around it, and kept reworking it.

                      The system in simple terms
                      • The program. A Python program connected to a broker through its API. That's where it got live prices and news, and where it placed its orders.
                      • The scanner. All day, a scanner ranked the biggest moves and freshest news across the market. It never traded itself.
                      • Two AI brains. The fast one looked over the top picks when speed mattered. The main one dug in with helper AIs, scored every idea, and decided how much to buy and at what price. Only the strongest went ahead; the rest were set aside with a note on why.
                      • The watcher. Plain code, no AI. It bought once the price reached the level the main brain set, and handled the stop losses and profit targets.
                      • The log. Each trade was logged with its reason, and I got a voice note on my phone.
                      How it protected itself

                      Every order had to pass fixed rules and went in with its exit planned. Where possible, the protective stop sat with the broker, so it held with the computer off. A loss limit for each stock, a cap on how often one stock could be traded in a day, and a daily halt were enforced in plain code the AI could not override. After a reboot, a watchdog restarted everything and re-ran any check it had missed.

                      A personal engineering project. Not financial advice.

                    4. Memory organized by topic

                      Built a shared memory so the agents keep every decision and correction, and search past conversations before asking again.

                      See more detailsHide details about the memory

                      A normal AI chat keeps one memory about you, and everything goes into the same place. This one is organized in categories: a separate memory for each topic and each project, so it never mixes up what belongs where.

                      Every decision is written down the moment it's made, one fact per note, and each agent loads the memory that belongs to its work before it starts. When I correct an agent, it records the mistake in its reasoning, not just the fix, so the same kind of error doesn't come back somewhere else. Every past conversation is kept and searchable, so an agent looks things up before it asks me again.

                      How it was built

                      One real problem at a time. The same kind of mistake kept coming back in new places, which led to a lessons file. An agent kept re-reading its whole history on every reply, which led to a small working memory plus a searchable archive. The result is a team I can hand almost anything to.

                    5. The job-application machine

                      It read job postings, wrote a tailored application for each one that fit, fact-checked it against my real work history and sent it on my go-ahead.

                      See more detailsHide details about the job-application machine

                      It read new job postings as they came in, kept only the ones that fit my rules, picked the right resume for the kind of work and wrote a short application for that one job. Every draft passed two checks: a wording check, and a fact check of each sentence against my real work history. I reviewed the first batch myself.
